User input is concatenated straight into a SQL query

Tree-sitter matched a string concatenation at line 15, column 15 of sample-app/src/auth.ts. The userId parameter flows into db.prepare() as query text, so a quote in the input can end the string and change the query. AEGIS rewrote it as a parameterized call, ran 4 tests including an injection payload, and opened PR #1 for review.

What goes wrong

userId is untrusted. A single quote ends the SQL string, and the rest of the input is parsed as SQL.

Why the fix holds

The ? slot binds userId as a literal value, so it can never become SQL syntax.
